# 층 구조

포털을 호스트 한 겹과 원격 배포단위 여러 겹으로 가르는 층을 정의한다.

## §1 호스트

호스트는 `portal` 앱 하나다. 라우팅과 인증만 갖고, 화면 내용은 갖지 않는다.
어떤 타일을 어느 슬롯에 놓을지는 [조립 계약](wiring-spec.md) §1 이 정한다.

## §2 원격

원격 배포단위는 타일을 내보낸다. 예약 흐름은 `booking-core` 가 갖고, 편집 흐름은
`booking-authoring` 가 갖는다. 회의실·장비 마스터는 `room-core` 가 소유한다.
같은 예약 규칙을 `booking-cores` 쪽에 다시 두지 않는다.

## §3 공유 의존

`widgets-shared` 는 버튼·달력 같은 표시 요소만 갖는다. 여기에 예약 규칙을 넣으면
`booking-core` 의 경계가 무너지고, 편집 흐름과 예약 흐름이 공유 패키지를 통해 서로를
끌어당긴다 ([결정 기록](#design/decisions) ADR-004). 같은 규칙을 `booking-authoring` 이
다시 갖는 일도 여기서 시작된다.
