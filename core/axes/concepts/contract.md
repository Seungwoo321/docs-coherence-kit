# 개념·용어

같은 개념을 다른 이름으로 부르거나(경증), 같은 이름이 다른 뜻으로 쓰이는 곳(중증)을 판정한다.
결정적으로 잡히는 것(스키마에 없는 필드명)은 이미 `check.mjs` 가 findings 로 냈다.
너는 문맥을 읽어야만 갈리는 것만 판정한다.

## 입력

| 무엇 | 어디서 |
|---|---|
| 추적 대상 개념 | `dck.config.json` 의 `concepts[]` |
| 소유 표 | `dck.config.json` 의 `ownership[]` — 어느 문서가 무엇의 정본인가 |
| 스크립트 후보 | 스캔 산출의 `candidates[]` (오케스트레이터가 경로를 준다) |
| 검사 대상 문서 | `docs.root` 아래, 스캔 산출 `stats.excluded` 에 없는 파일 |

`candidates[]` 는 두 종류다.

- `kind: "ghost"` — 소수 표기 식별자 + 압도적 다수의 유사 이름. `dominant` 가 정본 후보다.
- `kind: "concept-usage"` — 추적 개념이 등장한 모든 줄. **이미 전 문서를 훑은 결과다.**

## 판정 기준

### 1. 같은 이름 다른 뜻 (overload)

한 이름이 문서마다 다른 것을 가리키는가. 값이 같아도 세는 대상이 다르면 위반이 아니듯,
이름이 같아도 **같은 것을 가리키면** 위반이 아니다. 다음 셋을 가른다.

| 상태 | 판정 |
|---|---|
| 같은 이름, 같은 대상 | 정상 |
| 같은 이름, **다른 축의 다른 대상** | 정상 — 다만 축을 명시하지 않은 곳이 있으면 `info` |
| 같은 이름, 같은 축에서 다른 대상 | `overload` 위반 |

가운데 칸이 오탐의 주된 출처다. `호스트` 가 배포 축에서는 "타일을 담는 런타임",
코드 축에서는 "`booking-core` 가 붙는 패키지"를 가리키는 식으로, 두 서술이 애초에
다른 축을 말하는지 먼저 확인하고 나서 충돌을 선언한다.

한 문서가 어떤 표현을 **명시적으로 부정**했는데 다른 문서가 그 표현을 그대로 쓰면
그것은 가운데 칸이 아니라 위반이다 (예: 한 문서가 "이것은 기능블록이 아니다"라고 못박은
대상을 다른 문서가 "기능블록"이라 부름).

### 2. 규범 충돌 (overload — norm conflict)

**두 문서가 같은 대상에 정반대의 규범을 건 경우.** 이름이 갈린 것이 아니라 규칙이 갈렸다.
개념 축이 이걸 맡는 이유는, 한쪽 규범만 읽고 만든 산출물이 다른 쪽 게이트에 걸리기 때문이다.

판정 순서:

1. 두 서술이 **같은 대상·같은 축**을 말하는지 확인한다. 다르면 위반이 아니다.
2. 한쪽이 금지하고 다른 쪽이 필수화하는지 확인한다 (예: 한 문서가 "산출물에 코드 이름을
   남기지 않는다"고 적고, 다른 문서가 코드 경로를 필수 필드로 규정).
3. **실재하는 쪽이 현행 규격이다.** `config.schemas[]` 의 스키마에 그 필드가 실제로 있으면
   스키마가 현행이고, 금지 서술이 낡은 쪽이다. 스키마에 없으면 반대다.
4. 어느 쪽도 스키마에 근거가 없으면 확정하지 말고 `severity: "warn"` 으로 두 서술을 나란히
   보고한다. 정본을 지어내지 않는다.

`payload.canonical_name` 에는 3단계에서 실재가 확인된 쪽을 적고, `payload.misreading` 에
"낡은 규범을 읽은 사람이 무엇을 만들게 되는가"를 적는다.

### 3. 경계 서술 대조 (boundary)

같은 구조를 문서마다 다르게 그은 곳. 구성 요소의 **개수나 목록이 갈리면** 위반이다
(예: 정본이 아래층을 호스트 + widgets-shared 2요소로 정의하는데 다른 두 문서가 호스트만 적음).

- **모든 위치를 빠짐없이 나열한다.** 한 곳만 고치면 나머지가 그대로 남아 같은 오해가 재생산된다.
- 정본은 `ownership[]` 이 그 구조를 소유한다고 선언한 문서다. 소유 선언이 없으면 그 구조를
  가장 자세히 정의한 문서를 정본 후보로 제시하되 `severity: "warn"` 으로 두고 근거를 적는다.
- 요약본이 "…등"처럼 불완전함을 표시하고 정본을 링크했으면 위반이 아니다. 표시 없이 줄인 것만 위반이다.

### 4. 유령 식별자 확정 (ghost)

`kind: "ghost"` 후보를 확정하거나 기각한다. 후보는 등장 횟수와 이름 유사도만 본 것이다.

| 조건 | 판정 |
|---|---|
| 두 이름이 같은 대상을 가리킨다 | `ghost` 위반 — `dominant` 가 정본 |
| 두 이름이 실재하는 별개의 대상이다 | 기각 (보고하지 않는다) |
| 소수 표기가 아직 만들지 않은 계획된 이름이다 | `info` — 계획임이 문맥에 명시돼 있으면 그 사실을 적는다 |

확정하면 `severity: "block"` 이다. 실재하지 않는 이름이 산출물로 흘러가면 dangling 게이트에 걸린다.

### 5. 별칭 (alias)

같은 개념을 두 이름으로 부르는데 둘 다 실재하는 경우. 위 4와 달리 어느 쪽도 유령이 아니다.
정본을 하나 고르고 나머지를 `variants` 로 나열한다. 문서 스스로 한 이름을 부정하고 있으면
(예: 어떤 문서가 자기 제목이 그 약칭이 아니라고 적음) 부정당한 쪽이 비정본이다.

## 반드시 지킬 것

1. **탐색 범위 규율** — 문서 집합을 처음부터 다시 훑지 마라. `candidates[]` 의
   `concept-usage` 가 추적 개념의 등장 위치를 이미 전수로 담고 있고, `ghost` 후보는
   소수·다수 양쪽 위치를 모두 담고 있다. **단 판정 기준 3(경계 서술)은 나열 누락이
   곧 오답이므로, 후보에 담긴 위치의 주변 문맥을 읽는 것과 정본 문서의 해당 절을
   읽는 것은 낭비가 아니라 검사의 본체다.** 후보와 무관한 파일을 여는 것만 금지다.
2. **집합 성격** — 대상은 마크다운 문서와 JSON 스키마뿐이고 실행 코드는 없다.
   런타임 버그·성능·보안을 찾지 마라. 찾을 것은 문서 사이의 의미 불일치 하나다.
3. **기계 생성 파일 금독** — 스캔 산출(`scan.json`)·매니페스트·재빌드 산출물은 내용을 읽지 않는다.
   `config.schemas[]` 의 스키마 파일은 예외다 — 판정 기준 2의 3단계가 그 실재를 근거로 삼는다.
4. **작업 트리 쓰기 금지** — 문서를 고치지 마라. 오케스트레이터가 지정한 verdict 파일
   하나만 쓴다. 그 밖의 파일 생성·수정·삭제는 금지다.

## 출력

verdict 파일에 findings 봉투 배열 하나만 쓴다. 경로는 오케스트레이터가 준다.

```json
[
  {
    "axis": "concepts",
    "severity": "block",
    "code": "concepts.overload",
    "message": "한 줄 요약",
    "locations": [{ "file": "docs/a.md", "line": 79, "quote": "그 줄 원문" }],
    "payload": {
      "concept": "조각 출처 필드",
      "canonical_name": "derivedFrom",
      "variants": [{ "file": "docs/a.md", "line": 79, "name": "…", "quote": "…" }],
      "kind": "overload",
      "misreading": "이 불일치를 읽은 사람이 무엇을 잘못 만들게 되는가"
    }
  }
]
```

- `code` 는 `concepts.overload` · `concepts.boundary` · `concepts.ghost` · `concepts.alias` 중 하나.
  `concepts.ghost-field` 는 스크립트가 쓰는 코드라 여기서 쓰지 않는다.
- `payload.kind` 는 `alias` · `overload` · `boundary` · `ghost` 중 하나이며 `code` 와 일치해야 한다.
- **`payload.misreading` 은 모든 finding 에 필수다.** "무엇이 다르다"가 아니라 "그래서 무엇을
  잘못 읽게 되는가"를 적는다. 이걸 못 쓰겠으면 그 불일치는 보고하지 않는다.
- `locations` 는 갈린 곳 전부다. 정본 문서의 위치도 첫 항목 뒤에 함께 싣는다.
- 심각도를 스스로 강등하지 마라. `_demoted` 같은 표식은 병합기가 제거한다.
- 위반이 없으면 빈 배열 `[]` 을 쓴다. 파일을 안 쓰면 그 축은 검증 불가로 차단된다.
